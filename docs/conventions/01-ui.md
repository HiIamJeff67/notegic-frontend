# UI Conventions

## Foundation

- Use Tailwind CSS v4 utilities for layout, spacing, responsive behaviour and component-local appearance.
- Use the shadcn-style primitives in `src/components/ui/` for controls and overlays. They own Radix accessibility behaviour and `data-slot` attributes.
- Compose application patterns in `src/components/commons/`, `core/`, `menus/` and `panels/`; do not recreate Button, Dialog, Sheet, Menu, Input or Tooltip from raw HTML.
- Use Radix directly only when adding a missing primitive to `src/components/ui/`. Feature code should consume the local wrapper.
- Use `lucide-react` for general UI and action icons. Use custom icons only for Notegic-specific concepts.

## Composition and interaction

- Prefer an existing UI primitive, then an existing common component, before introducing a new component.
- Keep each interactive control accessible: icon-only controls need an `aria-label` or a visible tooltip; destructive actions need the destructive variant/state.
- Use `ContextMenuItem`, `DropdownMenuItem` and related wrappers for menu rows so keyboard behaviour and density remain consistent.
- Use `Button` rather than a raw `button` unless a primitive explicitly needs a raw trigger. `Button` publishes `data-slot="button"` and `data-size` for shared styling.
- Use the entity icons exported from `src/components/icons/WorkspaceEntityIcons.ts` whenever rendering a workspace entity.

## Responsive layout

- Page content must have `min-w-0` in flex layouts and must wrap or stack instead of overflowing.
- App-only pages live below `_root`; public pages must be root routes and cannot rely on the app sidebar or account providers.
- Sheet, dialog and sidebar content must keep close/primary controls reachable at narrow widths.
